# 每日 Token 上限单位输入 UI 自检

- 日期：2026-11-19
- 受众：在 DSH 中设每日调用熔断阈值的使用者。
- 基调：沿用现有限额设置的中性灰、紧凑控制和原字体；无需改页面骨架或引入新依赖。
- 首屏骨架：原设置行保留；Token 行为标签 + 数值输入 + 单位选择，消费行维持现有编辑方式。

## 交互与数值

- Token 数值允许 0–999，单位为亿（100,000,000）、千万（10,000,000）、百万（1,000,000）；三种单位最多都是 999，对应 999 亿（99,900,000,000）、999 千万（9,990,000,000）、999 百万（999,000,000）Token。空值/0 表示不限。
- 保存时换算为实际整数 Token 写入原配置，熔断仍比较实际累计 Token 与存储阈值；例如 2 亿保存为 `200000000`。
- 编辑已有上限时按量级选择合适单位回显；在当前编辑周期里保留用户选的单位。
- 自定义单位会进入原有状态阈值与熔断流程，不改变官方/本地数据源规则。

## 自检

- C：控制位于原紧凑限额行，数字输入 `min=0, max=999`；输入在有限空间中可收缩，单位选择固定 64px，防止溢出。
- D：单位是独立原生 `<select>`，输入和选择器各有 `aria-label`，键盘可操作。
- G：已有值回显、空值、0、单位上限和分数 Token 校验；超过每单位 999 时输入框直接标红（`--d-danger` 边框与文字）、`aria-invalid` 同步，并在字段下方显示红色提示「每种单位最多 999，超出不会保存」；失焦不写入配置，设置底部的说明区保持原文，不再重复上限文案。
- 验证：输入 2 亿、999 千万、999 百万分别换算并回显；三种单位各取上限 999，断言存储值为 999×单位、回显仍为 999/原单位，并用真实预算流验证阈值前一 Token 放行、达到阈值及以上熔断；`1000` 在任一单位都被拒绝。消费限额保存时保持原值。
- 视觉：用 `src/panel.css` 真实规则在 290×240 的固定设置面板里渲染限额设置，超限状态见 `token-budget-invalid.png`；面板无滚动溢出（内容 138px ≤ 可用高度），提示位于字段下方、说明文案上方，单位选择和消费行维持原样。
